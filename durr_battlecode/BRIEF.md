# durr_battlecode: brief (from `battlecode_main`, 2026-09-30)

You run a **second, separate team** in UNSW Battlecode 2026 (https://game.battlecode.au).
- **Goal:** climb the ladder as fast as possible, starting from our best bot.
- **Game:** a snake game ("dragons") on a torus with kelp walls and portals. Rules are in `../notes/01-game-rules.md`.
- **Bot:** C++; one process per dragon; 7x7 vision; sonar is the only communication.

## 0. Hard rules
1. **Where you may write.** You may create, edit and run things only inside `durr_battlecode/`. Everything else in the repo is **read-only** for you. Read and research anything you like: repo notes, replays, the web, the game docs.
2. **Never delete files.** Move unwanted things to `durr_battlecode/archive/`.
3. **Your API key is separate.** NEVER run plain `unswbc auth set`. That overwrites `~/.unswbc/keys.json`, which belongs to the main team ("Cache me outside"), and would break it. Instead:
   - Store your key with `HOME=$PWD/.home unswbc auth set <YOUR_KEY>`, run from inside `durr_battlecode/`. It then lives in `durr_battlecode/.home/.unswbc/keys.json` (git-ignored).
   - Run **every** `unswbc` command with that HOME, e.g. `HOME=$PWD/.home unswbc submit bot -n d1 -d "..."`.
   - The toolkit is at `~/.local/bin/unswbc`. If HOME is overridden and it's not found, call it by its full path.
   - `tools/api.py` in your folder already reads your key from `.home/`, never from `~/.unswbc`.
   - Never print, log or commit the key.
4. **Your API usage.**
   - You may GET and POST with your own key: challenges, ranked and unranked.
   - Never change team settings. Never create or regenerate keys.
   - Your 60 games/hour challenge budget is your own team's and is separate from ours.
5. **CPU etiquette.** This laptop is shared with the main session and gets hot.
   - Run at most **one local test batch at a time machine-wide**, with **`--jobs 3`** at most.
   - Check first: `ps aux | grep -E "pool.py|arena.py|unseen_eval" | grep -v grep`. If the main session's batch is running, wait.
   - Prefer server tests (unranked challenges); they cost no local CPU.
6. **Git is read-only** for you (status, log, diff only). The main session commits your folder.
   - Add **no AI attribution** anywhere: no Co-Authored-By, no "generated by".
7. Keep a timestamped log in `durr_battlecode/notes/LOG.md`.

## 2. How we test (lessons learned the hard way)
- **Local self-play is noisy.**
  - Run from `durr_battlecode/`: `python3 tools/pool.py "bot:-DFLAG=1" --pool variants/v31 --maps autarky,dilemma --seeds 4 --jobs 3`.
  - `tools/unseen_eval.py` runs the unseen-map sets gen/blind/lesson/gated, plus a held-out set with `--holdout`. Tune on nothing held-out.
- **Forensic arguments mislead.** Several "obvious bug fixes" lost on the server, e.g. BOX_HEAD_GUARD went 7/20 against 11/20.
  - **Only a server A/B against real top teams decides.**
  - Method: submit the candidate, then launch unranked challenges vs the top 10 on the relevant maps with `tools/launch_later.py`, using `CH_MAPS=<map ids>`, a JSON template of teams, and an output dir.
  - Compare against a baseline batch on the same opponents and maps.
- **Map ids:** Schooltime 9, Portals 20, Slithery 21, QoS 7, Default 4, Trophy 11, Dilemma 17, Autarky 19, Devil 13, Trauma 15.
- **Rate limit:** a **rolling** 60 games/hour per team. Ranked games also reach whatever version is live, at any time.
- **Before any submit:** run one sandbox game, `HOME=$PWD/.home unswbc run maps/devil.map bot variants/v31 --sandbox --no-replay`, and check the max compute points are well under 100M.
